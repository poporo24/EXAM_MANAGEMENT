Stage 1: Super Admin System Initialization

Actor: Super Admin • Goal: System setup and user management.

  • Log in as Super Admin.
  • Navigate to User Management. Show how Super Admins can add and manage all account tiers (Admins, Secretaries, Proctors, Students).
  • Show how roles dictate exact portal access limits.
2

Stage 2: Data Import & Availability Assignment

Actor: Admin • Goal: Bulk onboarding.

  • Log in as Admin.
  • Go to Dashboard and demonstrate the robust CSV Import Modals for Rooms, Instructors, and Exams.
  • Point out that the Instructor CSV parser automatically reads the availability column (e.g., "Mon 07:00-12:00") and applies it across the active exam period.
  • Go to Faculty, select an instructor, and click the Calendar icon to show the Admin Proctor Availability manager where Admins set exact shift times for proctors.
3

Stage 3: Cross-Institute Subject Aliasing

Actor: Admin • Goal: Linking identical courses.

  • Go to the Subjects tab.
  • Explain the CCA curriculum problem: Identical syllabi are taught under different codes (e.g., ICSLIS `IT201` and IBM `BUS105`).
  • Select both subjects via the checkboxes and click Link Selected.
  • Show how they are now bound in an Alias Group, forcing the auto-scheduler to bundle them in the exact same room and time to save resources.
4

Stage 4: The AI Auto-Scheduler Engine

Actor: Admin • Goal: Generating the master schedule.

  • Go to the Schedule tab.
  • Click Run Auto-Scheduler.
  • Explain the 4 strict constraints it evaluates during execution:
    1. Student Wellness: Max 2 Major subjects per day per section.
    2. Instructor Neutrality: Faculty cannot proctor their own taught subjects.
    3. Accessibility: PWD instructors are confined to ground floor/accessible rooms.
    4. Logistics: Applies a 15-minute travel buffer between different buildings.
    5. Availability: Honors the strict time slots set by the Admin in Stage 2.
5

Stage 5: Manual Overrides & Live Conflict Detection

Actor: Admin • Goal: Handling exceptions safely.

  • While on the Schedule matrix, click an exam to manually Edit it.
  • Attempt to assign a Proctor to a time slot where they are unavailable, or to a room that is already booked.
  • Showcase the resulting Error Modal, proving the system actively prevents human error during manual adjustments.
6

Stage 6: The Proctor Experience

Actor: Proctor • Goal: Viewing assignments.

  • Log out and log in as a Proctor.
  • Show the Proctor Dashboard highlighting total assigned hours.
  • Direct attention to the My Assigned Availability widget, showing the proctor the exact dates/times the Administration has cleared them for duty.
  • Show the button to Report Absence in case of emergency.
7

Stage 7: Secretary Paper Lifecycle & Absences

Actor: Secretary • Goal: Operational tracking.

  • Log out and log in as Secretary.
  • Demonstrate the live timeline tracking of exam papers: Pending → Collected → Returned.
  • Show the Absence Reports tab where secretaries can assign substitute 'Reliever' proctors dynamically when someone calls in sick.
8

Stage 8: Student Portal

Actor: Student • Goal: Accessing schedule.

  • Log out and log in as Student.
  • Show the clean, read-only Timetable.
  • Demonstrate that students only see exams for their specific section and subjects.
  • Click the Download PDF / Print button.
9

Stage 9: Reports & Analytics

Actor: Admin/Super Admin • Goal: Auditing and exporting.

  • Log back in as Admin and go to Reports.
  • Show the Proctor Hours report ensuring fair distribution of workload.
  • Show Room Utilization efficiency.
  • Click Export to Excel/CSV to demonstrate external system compatibility (CHED reports).
